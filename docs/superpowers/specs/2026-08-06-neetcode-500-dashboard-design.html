한 번의 시도도 버리지 않는 SQLite 학습 원장

500개 문제의 정답 여부만 저장하지 않습니다. 매 시도의 코드, 테스트, 시간, 음성 설명, Codex 검수와 약점 변화를 연결해 “무엇이 얼마나 나아졌고, 다음에 무엇을 연습해야 하는지”를 문제별로 설명할 수 있게 설계합니다.

01

질문에 대한 짧은 답

세 가지 모두 가능합니다. 핵심은 “현재 상태 한 줄”이 아니라 “시도와 근거를 계속 추가하는 원장”으로 SQLite를 쓰는 것입니다.

YES · EVERY ATTEMPT

매번 얼마나 발전했는가?

같은 문제에서 조건이 비슷한 이전 시도와 인식·코딩·디버깅·설명 시간, 테스트, 수정 횟수, blind 성공률을 비교합니다.

YES · PER PROBLEM

문제마다 약점이 무엇인가?

테스트, Codex, 자기평가, 타이머가 남긴 근거를 약점 관찰로 저장하고 해결·재발까지 별도 사건으로 기록합니다.

YES · CHERRY-PICK

원하는 약점만 골라 훈련?

약점·패턴·난도·언어·단계·최근 결과·기한으로 필터링하고 수동 연습 요청을 만들 수 있습니다. 필수 복습 이력은 건드리지 않습니다.

02

한 시도를 하나의 학습 사건으로

시도 도중에는 임시 저장할 수 있지만, 제출을 확정한 뒤에는 원본을 덮어쓰지 않습니다. 정정이나 “이 약점은 잘못 잡혔다”는 판단도 새 사건으로 남깁니다.

01 · ASSIGN

문제 배정

필수 스케줄 또는 사용자가 고른 연습 요청에서 시작합니다.

02 · ATTEMPT

시도 생성

문제별 sequence 번호, 단계, 언어, Full/Compact, Coach/Blind를 고정합니다.

03 · EVIDENCE

근거 묶기

코드, 테스트, 시간, 음성·문자 설명, Codex 리뷰를 attempt에 연결합니다.

04 · DIAGNOSE

약점 관찰

근거·출처·심각도와 추천 훈련을 기록합니다. AI 추정은 AI라고 표시합니다.

05 · SCHEDULE

다음 행동

결과에 따라 다음 필수 복습 또는 사용자의 선택 훈련을 만듭니다.

ATOMIC 학술 결과 확정은 하나의 SQLite 트랜잭션입니다. Codex가 일시적으로 불가능하면 잠근 제출물은 보존하되 PENDING_AI_REVIEW로 멈추며, 일부만 PASS로 남지 않습니다.

핵심 attempts 테이블의 제약조건 예시 보기 
CREATE TABLE attempts (
  id                    INTEGER PRIMARY KEY,
  problem_id            INTEGER NOT NULL REFERENCES problems(id),
  schedule_item_id      INTEGER REFERENCES schedule_items(id),
  practice_request_id   INTEGER REFERENCES practice_requests(id),
  sequence_no           INTEGER NOT NULL CHECK (sequence_no >= 1),
  encounter             TEXT NOT NULL,
  study_mode            TEXT NOT NULL CHECK (study_mode IN ('COACHED','BLIND','OPEN')),
  prompt_language       TEXT NOT NULL CHECK (prompt_language IN ('KO','EN')),
  attempt_format        TEXT NOT NULL CHECK (attempt_format IN ('FULL','COMPACT')),
  lifecycle_status      TEXT NOT NULL,
  academic_result       TEXT CHECK (
    academic_result IS NULL OR academic_result IN ('PASS','RETRY','FAIL')
  ),
  assistance_violation  INTEGER NOT NULL DEFAULT 0 CHECK (assistance_violation IN (0,1)),
  started_at_utc        TEXT NOT NULL,
  finalized_at_utc      TEXT,
  study_date_kst        TEXT NOT NULL,
  semantic_contract_hash TEXT NOT NULL,

  UNIQUE (problem_id, sequence_no),
  CHECK (NOT (
    study_mode = 'COACHED'
    AND academic_result IS NOT NULL
  )),
  CHECK (NOT (
    study_mode = 'BLIND'
    AND academic_result = 'PASS'
    AND assistance_violation = 1
  )),
  CHECK (NOT (
    lifecycle_status = 'SYSTEM_ERROR'
    AND academic_result IS NOT NULL
  ))
) STRICT;

07

화면은 SQL View로 설명 가능하게

Codex에게 “내 실력 점수 만들어줘”라고 맡기지 않습니다. 원장의 사실을 재현 가능한 View로 계산하고, AI 관찰은 출처가 표시된 하나의 근거로만 사용합니다.

v_attempt_timeline

모든 시도와 근거 자료 상태, 원본 지표, 같은 조건의 이전 시도 대비 변화량.

v_problem_progress

문제별 최신 단계·결과, 다음 due, blind pass 비율·streak, 첫/최신 시간, 열린 약점 수.

v_open_weaknesses

최신 상태, 재발 수, 최대 심각도, 마지막 발견일, 근거 attempt와 추천 drill.

v_practice_candidates

priority tier, reason code, 목표 약점, 제안 언어·형식이 보이는 연습 후보.

v_pattern_risk

패턴·난도·언어·blind 단계별로 반복되는 약점을 집계해 넓은 취약 영역 발견.

v_daily_load

오늘의 필수 복습, 추가 연습, 예상 시간과 밀린 debt를 분리해 보여주는 용량 View.

08

깨지지 않는 제출과 백업

학습량이 크지 않으므로 속도보다 보존과 재현성을 우선합니다. 잠근 제출물은 먼저 안전하게 보존하고, 학습 판정과 다음 일정은 필요한 근거가 모두 준비된 뒤 한 번에 확정합니다.

BEGIN IMMEDIATE동시 확정을 막고 write lock 확보
LOCK CODE최종 코드와 user tests의 hash 고정
ACCEPT RUN결정적 test run과 case result 연결
ATTACH VOICE확정 transcript와 rubric 저장
CHECK REVIEWCOMPLETE만 진행. 불가하면 outcome 없이 PENDING 보존
DIAGNOSE약점 관찰·상태 사건과 outcome 기록
COMMIT다음 schedule item까지 한 번에 확정
FK

Foreign keys ON

존재하지 않는 문제·attempt·관찰을 참조하는 고아 데이터를 차단합니다.

WAL

WAL + synchronous FULL

읽는 화면을 유지하면서 작은 쓰기를 안전하게 확정합니다.

UTC

UTC + Asia/Seoul date

정확한 순간은 UTC, 학습 캘린더는 KST 날짜로 쿼리합니다.

5S

busy timeout

백업과 화면 저장이 잠깐 겹쳐도 즉시 실패하지 않게 5초 기다립니다.

CHK

CHECK constraints

AI 도움 위반이 있는 blind PASS, system error의 academic result 같은 모순을 DB가 거부합니다.

BKP

검증된 atomic backup

SQLite backup API, artifact manifest, content hash와 integrity_check를 함께 검증합니다.

연결할 때마다 적용할 SQLite 설정 
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL;
PRAGMA busy_timeout = 5000;

Proposed final decision

현재 설계의 확정안
