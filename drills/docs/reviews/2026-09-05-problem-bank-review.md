## 발견한 문제와 수정

### 정상 구현도 실패하는 잘못된 예시

`nearest_value`와 `pair_sum_count`의 빈 입력 예시에서 `target` 인수가 빠져
CI0766·CI0772·CI0786·CI0792가 올바른 함수 시그니처로도 테스트를 통과할 수
없었습니다. 예시를 고치고, 생성된 모든 공개 호출의 인수를 함수 시그니처에
정적으로 대조하는 검사를 추가했습니다. CI0786 슬롯은 새 순열 과제로 교체했습니다.

### 조건 분기와 원본 변경을 놓치는 Basic 테스트

OR/AND 문제에서 한쪽 조건만 검사하는 오답이 기존 테스트와 소스 검사를 모두
통과했습니다. 각 조건이 독립적으로 참인 경우, 둘 다 참/거짓인 경우,
경계값을 추가했습니다. 복사본을 반환해야 하는 문제는 호출 뒤 원본까지 비교합니다.

재현 가능한 회귀 테스트는 정상 구현 37개를 받아들이고,
누락된 분기 오답 19개와 원본 변경 오답 14개를 거부합니다.
PB0213은 비활성 인덱스 추출로, PB0272는 `None`과 빈 문자열을 구분하는
이름 목록 변환으로 교체했습니다.

### Coding의 모호한 계약과 판별력 부족

12개 계약군의 예시와 규칙을 보강했습니다. 주요 내용은 다음과 같습니다.

- RPN 나눗셈: 음수에서 0 방향 절삭, 큰 정수를 float로 바꿀 때의 정밀도 손실.
- 힙 구성 비교: 항상 `True`를 반환하면 통과하던 과제를 두 실제 pop 결과를 반환하도록 변경.
- BFS: 사이클·중복 간선·인접 목록이 없는 정점.
- 두 수의 합: 중복이 있을 때 선택할 인덱스의 우선순위.
- Hash join과 시간별 조회: 같은 키·시각이 반복될 때 마지막 입력을 채택하는 규칙.
- 동형 문자열: 길이와 역방향 일대일 대응.
- 단어 분할: 빈 사전 토큰을 재귀 전이로 사용하지 않는 규칙.
- 작업 스케줄러: 비선점 실행, 현재 도착한 작업만 선택, 유휴 시간 이동.
- Lazy deletion: 존재하지 않는 값의 삭제가 미래 삽입을 지우지 않는 규칙.
- 정렬 질의: 빈 입력·중복·경계 조건.

수정은 같은 템플릿에서 생성된 모든 반복 슬롯에 적용했습니다.

## 학습 적절성 판정

**Basic은 기초 문법을 학습한 뒤 사용하는 자동화 드릴로 적절합니다.**
초반부터 함수·리스트·딕셔너리가 등장하고 805개의 제한시간이 120초로 같으므로,
파일 순서 자체가 설명을 포함한 입문 강의라고 해석하면 안 됩니다.
각 주제의 v01로 진단하고 막힌 주제의 변형을 선택하세요.

**Coding은 240개 핵심 계약을 먼저 학습하고 나머지 560개를 간격을 둔 복습에
사용하는 편이 적절합니다.** 같은 날 동일 과제를 여러 번 풀고 신규 진도로
계산하는 구조를 피했습니다. 1,620개를 전부 끝낼 때까지 실제 알고리즘 문제
풀이를 미룰 필요는 없습니다.

기존 일정 문서에는 File & JSON 300개가 계획되어 있지만 현재 생성된 별도
문제은행은 없습니다. 따라서 이번 검토·공개본의 실제 범위는 1,920개가 아닌
1,620개입니다. 현재 파일·JSON·CSV 드릴은 주로 문자열 파싱과 경로 조작 범위입니다.

공개 assert와 AST 검사는 모든 유효 입력, 시간복잡도, 스스로 풀었는지,
장기 기억을 증명하지 않습니다. 참조 구현은 테스트 파일 안에만 있고, 사용자용
문제 파일은 빈 스타터 또는 의도적으로 고쳐야 하는 버그 스타터를 유지합니다.
