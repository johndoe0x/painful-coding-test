# 답안 저장과 GitHub 업로드

문제 파일에 풀이를 작성한 뒤 아래 명령을 실행합니다. 기본 목적지는 공개 저장소
`johndoe0x/painful-coding-test`의 **루트 `answers/` 폴더**입니다.
업로드한 풀이와 검증 요약은 누구나 읽을 수 있습니다.

## 한 문제 올리기

Python 3.11 이상과 로그인된 GitHub CLI(`gh`)가 필요합니다.
최초 한 번 `gh auth login`으로 해당 저장소에 쓰기 권한이 있는 계정으로 로그인하세요.

```bash
# 로컬 학습 폴더 또는 clone한 저장소의 drills/ 안에서 실행
python3 -B submit_answer.py PB0001
python3 -B submit_answer.py CI0022
```

다음 순서로 처리합니다.

1. manifest에서 지정한 문제 파일을 찾아 공개 예시·self_test·필수 소스 검사를 새로 실행합니다.
2. PASS한 코드와 검증한 코드의 SHA-256이 일치하는지 확인합니다.
3. 로컬 `answers/<문제 ID>/<소스 SHA-256>/`에 버전을 저장합니다.
4. GitHub의 같은 경로에 `solution.py`와 `result.json`을 한 커밋으로 추가합니다.
5. 성공하면 커밋 URL을 출력합니다. 이미 같은 답안이 있으면 `ALREADY_UPLOADED`를 출력합니다.

문제 원본을 옮기거나 문제은행의 빈 스타터를 GitHub에서 덮어쓰지 않습니다.
업로드는 직접 지정한 ID 또는 명시적으로 선택한 `--all` 범위만 대상으로 합니다.
개인 복사본·보관 답안·학습 로그를 문제은행에서 임의로 찾아 올리지 않습니다.

`solution.py`는 선택한 문제 파일 전체(문제 설명, 본인 풀이, self_test)입니다.
`result.json`에는 ID·소스 해시·검증 시각·Python 버전·통과 개수·필수 소스 검사만
저장합니다. 실행 중 `print`와 로그는 로컬에 표시하고 결과 요약에는 넣지 않습니다.

## 푼 문제 한꺼번에 올리기

```bash
# 현재 작성한 문제들을 새로 검사하고 PASS한 답안만 한 커밋으로 업로드
python3 -B submit_answer.py --all

# 일괄 검사·로컬 저장만 수행
python3 -B submit_answer.py --all --local-only

# 로컬에 저장한 답안들을 한꺼번에 재전송
python3 -B submit_answer.py --all --retry
```

`--all`은 Basic/Coding manifest에 등록된 파일만 확인합니다. 스타터 그대로인
문제와 실행 코드에 `NotImplementedError`가 남은 문제는 건너뜁니다. 이름이 비슷한
개인 복사본이나 `_preserved_answers/`는 업로드 후보에 넣지 않습니다.

작성한 코드에 문법 오류·오답·시간 초과가 있으면 해당 ID를 `FAILED`로 표시하고
나머지 문제를 계속 검사합니다. 통과한 답안들은 한 커밋으로 올립니다. 마지막에는
통과·실패·미작성·미완성 개수를 표시하며, 업로드할 답안이 없으면 GitHub에 접속하지 않습니다.

일부 실패가 있으면 종료 코드는 **2**입니다. 이때 통과한 답안의 저장·업로드는
완료되었을 수 있으므로 출력된 결과와 커밋 URL을 확인하세요. 정상 처리와 미작성만
있는 경우는 0, 업로드 자체 실패는 1입니다. 이미 올라간 같은 버전은 중복 커밋하지 않습니다.

`--all --retry`는 현재 코드를 재검증하지 않고, 등록된 문제별 마지막 로컬 저장본을
사용합니다. 현재 코드를 고치는 중이라도 이전 PASS 버전이 전송될 수 있습니다.
특정 문제만 재시도하려면 ID를 나열하거나 `--version`으로 정확한 버전을 선택하세요.

## 오프라인 저장과 재시도

```bash
# 네트워크 없이 검사하고 로컬 버전만 저장
python3 -B submit_answer.py PB0001 --local-only

# 마지막으로 저장한 PB0001 답안을 업로드
python3 -B submit_answer.py PB0001 --retry

# 특정 예전 버전을 지정해 업로드
python3 -B submit_answer.py PB0001 --retry --version <64자리-소스-SHA256>
```

`--retry`는 현재 편집 중인 코드가 아니라 저장된 답안을 사용합니다. 이미 검사한
버전을 보관·재전송하는 동작이며, 변경된 현재 코드나 최신 문제 조건을 재검증하는
명령은 아닙니다. 현재 코드를 새로 검사하려면 `--retry` 없이 실행하세요.

같은 코드의 로컬 결과는 최초 저장본을 유지합니다. 코드가 달라지면 새 해시 경로에
저장되므로 이전 풀이가 남습니다. 다른 기기에서 같은 코드를 올렸어도 원격에 같은
소스와 유효한 결과가 있으면 최초 원격 기록을 유지합니다.

로컬 `answers/<ID>/latest.json`은 마지막으로 선택한 버전을 가리킵니다. 이전 코드로
돌아와 다시 실행했어도 `--retry`는 방금 선택한 그 버전을 사용합니다. 이 선택 기록은
GitHub에 업로드하지 않습니다. 오류 시 출력되는 재시도 명령에는 정확한 버전과 목적지가 포함됩니다.

## 여러 문제와 다른 저장소

```bash
# 지정한 두 문제를 모두 검사한 뒤 한 커밋으로 업로드
python3 -B submit_answer.py PB0001 CI0022

# 자신이 소유한 다른 기존 저장소 또는 브랜치 지정
python3 -B submit_answer.py PB0001 --repo OWNER/REPO --branch main

# 무한 루프 등으로 검증이 끝나지 않을 때 제한 시간 조절 (최대 300초)
python3 -B submit_answer.py PB0001 --timeout 10
```

ID를 직접 나열한 경우에는 하나라도 실패하면 해당 명령에서 GitHub에 업로드하지 않습니다.
`--all`의 통과 답안만 모으는 방식과 구분됩니다. `--all`과 ID 나열은 함께 사용할 수 없습니다.
그 전에 통과해 로컬에 저장된 버전은 남습니다.
새 저장소나 브랜치를 자동으로 만들지는 않습니다. 다른 저장소는 README와 기본
브랜치를 미리 준비하고 쓰기 권한을 확인하세요.

## 오류가 날 때

- `FAIL`: 원래 문제 파일을 수정하고 다시 실행합니다. 미완성 코드는 업로드하지 않습니다.
- 검증 도중 코드 변경: 파일을 저장한 후 명령을 다시 실행합니다.
- 로그인·권한: `gh auth status`를 확인합니다.
- 네트워크 오류·동시 업로드 충돌: 로컬 저장본이 있으면 `--retry`로 재시도합니다.
- 원격의 같은 버전 경로가 다른 내용이면 덮어쓰지 않고 오류를 표시합니다.

업로드는 [GitHub Git trees API](https://docs.github.com/en/rest/git/trees#create-a-tree)의
기존 트리를 기반으로 만들고, [참조 갱신](https://docs.github.com/en/rest/git/refs#update-a-reference)은
`force=false`로 수행합니다. 다른 변경이 먼저 반영되어 충돌하면 강제 푸시하지 않습니다.
응답을 받지 못해 성공 여부가 불명확한 경우에도 같은 버전으로 재시도하면 원격 기록을 먼저 확인합니다.

이 도구의 PASS는 **로컬 공개 예시·self_test·필수 문법 검사** 결과입니다.
서버의 독립 채점이나 AI 코드 리뷰, 암기 여부 인증을 뜻하지 않습니다.
소스 해시는 파일과 결과를 연결하며, 학습자가 로컬 기록을 조작할 수 없다는 보안 인증은 아닙니다.
